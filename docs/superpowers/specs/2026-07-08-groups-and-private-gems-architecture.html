AgentGem · Groups & Private Gems

Private gems are a separate credentialed surface — not a filtered view of the public one

Two surfaces, not one filter

  • • Public routes carry WHERE visibility = 'public' — a predicate that never depends on the caller, so it cannot be got wrong per-user
  • • publicGemCache stays global and identity-free because no private row can enter it
  • • PUBLIC_READ_PATHS is not modified — the CORS config that broke /minigames once already stays put
  • • A leak now requires adding a route, not forgetting a filter

Two group kinds, two member sources

  • • federated — mirrors an external network, has a verified scope (GitHub org today, Slack workspace later)
  • • native — created inside AgentGem, no scope, uuid-addressed, invite-only
  • • Orthogonal to group_members.source: a federated group may hold invited guests
  • • Sync reconciler deletes only source='sync' — offboarding keeps working; guests were never GitHub's to revoke

What this spec does not do

  • • Does not split account_identities out of accounts — sequel
  • • Does not add Google OIDC or any new login provider — sequel
  • • Does not re-key published_by off the bare GitHub login — sequel
  • • Does not give native groups a usage dashboard — usage is attributed by repo owner and has no honest native equivalent
