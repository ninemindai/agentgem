AgentGem Identity Re-key — Authorization Model

PR #285 · feat/identity-rekey · after the engineering review · uuid authorizes, handle names

1 — Where the account's name lives (the write path)

One fact, one home. The role='self' mirror row is gone; the type system forbids its return.

2 — resolveOrgAccess: the single gate (the read path)

Strict precedence. An active installation's roster decides alone. No handler may re-derive "is this my own scope?" ahead of it.

The two authorization consumers

  • • uploadPublish — active installation → appOrgRole(login, scope); otherwise accountOwnsScope(accountId, scope) = handle match OR org row.
  • • deleteCatalogGem — owner_account_id !== null && owner_account_id === who.accountId.
  • • A NULL owner is owned by NOBODY. Fail closed. Never add a string-compare fallback for NULL — that is the hole the re-key closes.

buildOrgUsage is NOT the gate

  • • Membership boundary: EXISTS(org row in account_scopes) OR EXISTS("user".handle = scope).
  • • This decides which accounts' rows are aggregated into a dashboard — it does not decide who may read it. resolveOrgAccess does, upstream.
  • • Was an innerJoin(account_scopes) that only served the personal view because the mirror row happened to exist. EXISTS also cannot fan out the SUM()s.

Two different things named publishedBy

  • • catalog_gems.published_by — a DB column. Authorizes, via deleteCatalogGem. Being re-keyed onto owner_account_id.
  • • publishGem({ publishedBy }) — lands in the git registry index JSON. Authorizes nothing; it is public attribution, so it carries the handle, not a uuid. A uuid there names nobody.
  • • uploadPublish already authorizes with accountOwnsScope and needed no re-key.

The invariant to preserve

  • • "user".handle is the only home for an account's name. Never mirror it.
  • • Every "may this caller act on this scope?" question goes through resolveOrgAccess. Read via; never re-derive isSelf.
  • • Phase 2 (Google / Slack / X / passkey) adds writers to these paths. The ScopeGrant type is what stops them reintroducing the mirror.

Residual, by design

  • • A handle may still squat a GitHub org's name before the org onboards — isReserved has nothing to check until the org's first installation or settings write.
  • • Post-onboarding it grants no authorization (path 1 decides alone). What remains is username-registry squatting: /@org resolves to the squatter.
  • • Closing that means seizing a name in active use — a namespace policy, not a code fix.

Why one reviewer could not see it

  • • Each of the three writers was locally correct. The defect existed only in the relationship between them.
  • • Eleven per-task reviews and one whole-branch review passed. Both P1s lived at a seam no single diff contained.
  • • Both were reproduced against PGlite before the fix, and every regression test was proven discriminating by mutation.
